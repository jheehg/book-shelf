# 검색어 정규화 규칙 — 결정 (2026-09-30)

설계 문서 6-4: "캐시 적중률을 좌우하며 정답이 하나가 아니다. 구현 시 직접 정한다."
**기본안으로 정했다.** 캐시 키와 카카오로 보내는 검색어는 같은 값이다.

| 규칙 | 결정 | 이유 |
|---|---|---|
| 유니코드 | NFC로 합친다 | macOS에서 복사한 한글은 NFD라 같은 글자가 다른 키가 된다 |
| 공백 | 앞뒤 제거, 연속 공백은 하나로. **지우지는 않는다** | 공백을 지우면 카카오에 공백 없는 검색어가 가 결과가 달라질 수 있다. 키와 보낼 검색어를 따로 두면 복잡해진다 |
| 대소문자 | 소문자로 | "Harry"/"harry"는 같은 의도다 |
| 자모만 | 거부 | 입력 중인 "ㅅㄴ"은 검색 의도가 아니다 |
| 길이 | 2~100 코드포인트 | 설계 문서: 2글자 이상. 1글자는 캐시를 도배한다 |

서버도 2글자 규칙을 검사한다 — 앱의 디바운스를 지키지 않는 클라이언트가 있다.

나중에 볼 것: 카카오가 대소문자를 구분하는지("Harry"/"harry" 결과 비교). 구분한다면 소문자 규칙을 다시 본다.
